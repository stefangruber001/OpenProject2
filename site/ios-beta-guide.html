iOS Release — Quickstart

Canei Subirats · for someone who has shipped to the App Store before

The model: the app is a native shell over the live web app. Website changes reach the app automatically (pull-to-refresh) — no new build, no review. You only upload a build to change the native shell (icon, tabs, permissions). Everything below is that upload path, automated to one file + one command.

One-time · the app record (5 min, skip if done)

1

Register the bundle id

developer.apple.com → Identifiers → + → App → com.caneisubirats.erp. Prefer your own prefix? Change PRODUCT_BUNDLE_IDENTIFIER in the Xcode target and APP_BUNDLE_ID in fastlane/.env.default to match — one place each.

2

Create the app in App Store Connect

Apps → + New App → iOS · name Canei Subirats · pick the bundle id · SKU CANEI-ERP-IOS. No screenshots/description needed for internal TestFlight. Encryption compliance is pre-declared in the project — you won't be asked.

Fill once · fastlane/.env.default

From App Store Connect → Users and Access → Integrations → App Store Connect API, create a key with App Manager access and download the .p8 (once-only download). Then:

Key in .env.defaultValue / where
ASC_KEY_IDthe key's Key ID (10 chars)
ASC_ISSUER_IDthe Issuer ID at the top of that page (uuid)
ASC_KEY_P8_PATHpath to your saved AuthKey_XXXX.p8 (keep it outside the repo)
DEVELOPER_TEAM_IDdeveloper.apple.com → Membership → Team ID (10 chars)

Secrets stay local. fastlane/.env.default and every *.p8 are gitignored — nothing sensitive is committed. Store the .p8 in a password manager.

Ship · one command

cd ios
make setup          # installs fastlane, creates .env.default (fill it), once
make ship           # signs, auto-bumps build no., uploads to TestFlight

Managed signing runs through the API key — no manual certificates or 2FA prompts. On success the build appears in App Store Connect → TestFlight after a few minutes of processing.

Testers (once per person)

You

App Store Connect → TestFlight → Internal Testing → add testers (they must be under Users and Access; up to 100, no review, instant) → attach the build.

Each tester

Install TestFlight from the App Store → open the invite email → Install. Allow camera on first use so site-visit photos work.

Updating — what needs a build, what doesn't

ChangeActionTesters
Website content, prices, catalogue, documents, workflow, coloursNothing — publish the site as usualPull to refresh
App icon, splash, a tab, permissions, OS supportmake ship againUpdate in TestFlight
Go public on the App StoreAdd store listing → submit for reviewInstall from App Store

Hands-off alternative — GitHub

Add the four values as repo Secrets (ASC_KEY_ID, ASC_ISSUER_ID, ASC_KEY_P8 = the .p8 contents, DEVELOPER_TEAM_ID), then Actions → “iOS · TestFlight” → Run workflow. It only runs when you click it — never on ordinary pushes, so no failure emails.

Troubleshooting

“No account for team” in Xcode

Xcode → Settings → Accounts → add your Apple ID; target → Signing & Capabilities → pick the Team.

Project won't open

cd ios && ./setup.sh regenerates it cleanly (needs XcodeGen; the script installs it).

Auth / key errors from fastlane

Check ASC_KEY_P8_PATH points to the real file and the key has App Manager role. Re-download if lost (generate a new key).

Build stuck “Processing”

Normal for a few minutes; refresh TestFlight. It clears itself.

In one breath: register the id + create the app record (once) → fill fastlane/.env.default (four values) → make setup then make ship. Future app updates = make ship; future content updates = just publish the website.
