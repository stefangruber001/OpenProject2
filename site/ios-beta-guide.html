How this works & what you'll do

The app is a premium native shell around your existing website. The website stays the brain; the app makes it feel like a first‑class iPhone app and adds the camera, offline handling, share sheet and home‑screen icon.

The one idea that saves you the most time

When we change the website, the app updates itself — the operator just pulls down to refresh, or reopens the app. You only need to send a new TestFlight build when the native shell itself changes (rare: a new icon, a new tab, an OS requirement). Day‑to‑day content, prices, catalogue and workflow changes need no new build and no App Store review.

Part 2 · Developer Mac

Join the Apple Developer Program

TestFlight — Apple's official beta system — requires a paid Developer Program membership. This is a one‑time enrolment; renewal is yearly.

1

Open the enrolment page

On the Mac, go to developer.apple.com/programs/enroll and sign in with your company Apple ID. If you don't have two‑factor authentication on, Apple will ask you to turn it on first.

2

Choose the entity type

Select Company / Organization if enrolling as Canei Subirats, S.L. (recommended — the app is published under the company name and multiple people can be added). You'll need your company's legal name, address and a D‑U‑N‑S number (free; Apple links you to look it up — allow 1–5 business days if you don't have one yet). Choose Individual only if you want the fastest path and are comfortable publishing under a personal name.

3

Confirm your details & pay

Enter the company details exactly as they appear in official records, agree to the Apple Developer Agreement, and pay the €99/year fee. You'll get a confirmation email.

4

Wait for approval

Individual enrolments are often approved within a day. Company enrolments include a verification call/email from Apple — usually 1–3 business days. You cannot use TestFlight until this is Active.

While you wait

You can already open the project in Xcode and run the app on the iPhone Simulator (no membership needed) to see it working. You just can't send it to real devices via TestFlight until the membership is active.

Part 3 · Developer Mac

Create the app in App Store Connect

App Store Connect is Apple's web dashboard for your apps and testers: appstoreconnect.apple.com. Do this once the membership is Active.

1

Register the bundle identifier

Go to Certificates, Identifiers & Profiles → Identifiers → +. Choose App IDs → App, description “Canei Subirats”, and Bundle ID Explicit = com.caneisubirats.erp. Leave capabilities at defaults and Register.

2

Create the app record

In App Store Connect → Apps → + New App. Fill in:

  • Platform: iOS
  • Name: Canei Subirats (this is public; “Canei” shows under the icon)
  • Primary language: Spanish (Spain) or English
  • Bundle ID: select com.caneisubirats.erp from the list
  • SKU: any internal code, e.g. CANEI-ERP-IOS
  • User access: Full Access
3

You do NOT need the full store listing yet

TestFlight betas don't require screenshots, a description, or App Review for internal testers. You can add all that later, only when you decide to publish publicly. For now, creating the record is enough.

Export‑compliance: already handled

The app declares it uses no non‑standard encryption (ITSAppUsesNonExemptEncryption = false is set in the project), so Apple won't ask you the encryption question on every upload. Nothing to do here.

Part 4 · Developer Mac

Send the first build to TestFlight

Pick one of the three methods. If you've never done this before, use Method A — it's the most visual.

Method A — Xcode (most visual, recommended first time)

1

Open the project & sign in

Double‑click ios/CaneiSubirats.xcodeproj. In Xcode → Settings → Accounts, add your Apple ID (the one in the Developer Program).

2

Set the signing team

Select the CaneiSubirats target → Signing & Capabilities. Tick Automatically manage signing and pick your Team from the dropdown. Xcode creates the certificate and profile for you.

3

Choose the build destination

At the top of the window, set the device target to Any iOS Device (arm64) (not a simulator).

4

Archive

Menu Product → Archive. Wait for the build. When it finishes, the Organizer window opens with your archive.

5

Distribute to App Store Connect

Click Distribute App → TestFlight & App Store → Upload. Accept the defaults (automatic signing, upload symbols) and click through to Upload. Success shows a green tick.

6

Wait for processing

In App Store Connect → your app → TestFlight, the build shows “Processing” for a few minutes, then becomes available. Continue to Part 6 to add testers.

Part 4 · continued

Methods B & C — one command / one click

Once you've done Part 5 (the API key), these let you skip Xcode entirely for every future build.

Method B — fastlane (one command on the Mac)

In Terminal:

# first time only — installs the automation
cd ios
bundle install

# set your four secrets (from Part 5)
export ASC_KEY_ID=XXXXXXXXXX
export ASC_ISSUER_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
export ASC_KEY_P8="$(cat ~/Downloads/AuthKey_XXXXXXXXXX.p8)"
export DEVELOPER_TEAM_ID=XXXXXXXXXX

# build + upload to TestFlight
bundle exec fastlane beta

fastlane builds a signed release, auto‑increments the build number, and uploads it. When it prints “Uploaded to TestFlight”, go to Part 6.

Method C — GitHub (one click, no Mac needed after setup)

1

Add four repository secrets

In GitHub → the repository → Settings → Secrets and variables → Actions → New repository secret, add: ASC_KEY_ID, ASC_ISSUER_ID, ASC_KEY_P8 (paste the whole .p8 file contents), DEVELOPER_TEAM_ID.

2

Run the workflow

Go to the Actions tab → “iOS · TestFlight” → Run workflow. A Mac runner builds and uploads for you. It only ever runs when you click it — it will never fire on ordinary code changes, so it won't send failure emails.

Which should I use?

First ever build → Method A. After that, if you like Terminal → B; if you'd rather click a button in the browser → C. All three produce identical builds.

Part 5 · Developer Mac

The App Store Connect API key

Methods B and C sign in to Apple with a key file instead of your password, so there are no two‑factor prompts. Create it once. (Skip this part if you only ever use Method A.)

1

Open the Integrations page

App Store Connect → Users and Access → Integrations tab → App Store Connect API.

2

Generate a key

Click +, name it Canei CI, set access to App Manager, and Generate.

3

Copy the three values

You'll now see:

ValueLooks likeSecret name
Key ID2X9ABC1DEFASC_KEY_ID
Issuer ID69a6de70-…-1a2b3cASC_ISSUER_ID
The key fileAuthKey_2X9ABC1DEF.p8ASC_KEY_P8

Download the .p8 file now — Apple lets you download it only once. Keep it somewhere safe (a password manager). Its full text becomes the ASC_KEY_P8 secret.

4

Find your Team ID

developer.apple.com → Membership → Team ID (10 characters, e.g. AB12CD34EF). That's DEVELOPER_TEAM_ID.

Keep these private

The .p8 key and IDs can upload builds to your account. Never email them, never commit them to the repository, never paste them into a chat. Store them in GitHub Secrets or a password manager only. The project's .gitignore already blocks *.p8 from being committed by accident.

Part 6 · Operator iPhone

Invite testers & install

This is the only part your field users do. It takes about two minutes per person.

You (admin) — add the testers

1

Open TestFlight for your app

App Store Connect → your app → TestFlight. Under Internal Testing, click + next to “Internal Group” (or create a group “Canei Field”). Internal testers must be added under Users and Access first (up to 100, no App Review, instant).

2

Attach the build & invite

Select the processed build, add the testers' Apple ID emails, and Save. Each person gets an email invitation from TestFlight.

Each tester — on the iPhone

1

Install TestFlight

Open the App Store, search TestFlight (made by Apple), install it, and sign in with the Apple ID that received the invite.

2

Accept the invitation

Open the invitation email on the iPhone and tap View in TestFlight (or open TestFlight → Redeem and paste the code). Tap Install.

3

Launch Canei

The Canei icon appears on the home screen. Open it — you'll see the brand splash, then the live app. On first camera use it will ask permission; tap Allow so site‑visit photos work.

Add to Home Screen — the no‑account alternative

Testers can also just open the website in Safari and use Share → Add to Home Screen for a lightweight icon. TestFlight is the real app (camera, offline, share, updates); “Add to Home Screen” is a quick fallback if someone can't install TestFlight in time.

Part 7

What to test (beta checklist)

Run one real project end‑to‑end on the phone. Tick each item; note anything that feels slow, cut off, or confusing.

Navigation & feel

  • Splash appears, then the Home tab loads.
  • All four tabs switch instantly and keep their place.
  • Tapping the active tab returns it to the top / home.
  • The top progress line shows while pages load.
  • Pull down to refresh works on every tab.
  • Nothing is cut off on the left/right edges.

The real workflow

  • Enter your own company & client data (not the sample).
  • Take a site‑visit photo — it saves into the project.
  • Build an estimate → turn it into a quote.
  • Generate the quote & invoice PDFs.
  • Export the project folder (ZIP) → Save to Files works.
  • Share a document via the share sheet.

How testers report problems (built into TestFlight)

In TestFlight, a tester can take a screenshot and it is offered straight to “Share Beta Feedback”, or press‑and‑hold the app in TestFlight → Send Beta Feedback. Their note + a screenshot + device details arrive in App Store Connect → TestFlight → Feedback. Ask testers to describe: what screen, what they tapped, what they expected.

What we can fix without a new build

Almost all feedback about content, layout, wording, prices, catalogue, documents and workflow is a website change — it goes live the moment we publish, and testers just pull to refresh. Only feedback about the app frame (icon, tabs, splash, permissions, crashes) needs a new TestFlight build.

Troubleshooting & FAQ

The build shows “Missing Compliance” in TestFlight

Rare, because we pre‑declare it. If it appears, click the build and answer “Does your app use encryption? → None of the algorithms mentioned above / Standard only.”

“No account for team” / signing errors in Xcode

Xcode → Settings → Accounts → add your Apple ID; then on the target → Signing & Capabilities pick the Team. Make sure the Developer Program membership is Active.

The project won't open

In Terminal: cd ios && ./setup.sh. It installs a helper and regenerates the project cleanly, then opens it.

I want a different bundle id / company domain

Change PRODUCT_BUNDLE_IDENTIFIER in the project (and app_identifier in ios/fastlane/Appfile) to your value, register that id in Part 3, and rebuild. Do it before the first upload.

A tester didn't get the invite

Check the exact Apple ID email, look in spam, or send them the public TestFlight redeem code. Internal testers must also be listed under Users and Access.

Does the camera / photos work in the beta?

Yes. The app asks permission on first use; the site‑visit photo capture and the project folder both work through the native app.

How long can we stay in beta?

Each TestFlight build is valid for 90 days. Sending a new build resets the clock. There's no limit on how long you use TestFlight overall.
