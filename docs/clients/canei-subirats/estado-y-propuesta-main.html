Why it feels confusing — three real causes

Two "dev" branches, one wired up The preview is pinned to a branch name written into the workflow. Today's work sits on the other one, so it is invisible to the preview — while the watched branch is an exact copy of main and adds nothing.
It has drifted silently before The same hard-coded name once served nine-session-old content. Nothing failed, nothing went red — it was only noticed when somebody opened the link expecting to review recent work.
The instructions name both The project's own guide lists two branches, so each session picks one and work lands where the tooling is not looking. The rule and the workflow drift apart independently.

Deliberately not touched

The release pipeline stays exactly as it is. Build → test the real image against a real database with the restricted role → only then move the live tag → the server pulls it within a minute. There is no login key in the build system and no open door on the server; a bad release is undone by pointing the tag back, not by anyone logging in. Two past outages shaped that design and it is working.

The one thing we give up

Removing the preview leaves no non-production place to look at screen changes before they are live. Today that costs nothing — the preview has been an exact copy of main and nothing loads it. If you would rather keep a look-before-live step, the replacement is a review request with the built pages attached, not a branch name written into a workflow. Say the word and I will point the preview at main instead of deleting it — one line, same protection against drift.
