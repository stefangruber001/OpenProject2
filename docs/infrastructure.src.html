Page 1 · The whole picture

One system, one source of truth

Everything the company runs on lives in one place: a dedicated server in Germany. The phone app and the website are two doors into the same system — not two systems that copy each other. Whatever is typed on a phone at a job site is on the office laptop seconds later, because neither device keeps its own copy.

Page 2 · Data

Where your data lives, and how it moves

1

The three layers

What each part is responsible for — and what it is deliberately not allowed to decide.

Front end · what you see
The screens: home, project, clients, control tower, master data, finance, guide. Eleven pages, identical in the app and in the browser.
  • Draws the screens and forms
  • Sends every change to the server
  • Keeps no company data of its own
Back end · the rules
The application on the server. Every request passes through it; nothing reaches the database without it.
  • Checks who you are, on every request
  • Decides which company's data you may see
  • Stamps every change with your name
Database · the record
PostgreSQL. Two stores that matter to you day to day:
  • Documents — the register of quotes, invoices, projects, customers
  • Attachments — the site photographs, kept separately so the register stays fast
2

Two people at the same time cannot overwrite each other

Every save carries the version number it was based on. If somebody else saved first, the second save is refused rather than silently accepted — and the person is told to reload and re-enter. An afternoon's work can no longer disappear without a message.

An open page no longer shows yesterday's figures

A page used to read the data once and then show it all day. Now it asks the server "has anything changed?" when you come back to it. If nothing is half-typed it refreshes itself; if you are mid-form it offers, and never interrupts you.

One thing to know about older photographs

Photographs taken before 8 August 2026 were kept inside the phone or laptop that took them, and are not yet on the server. Anything taken from now on is stored centrally and backed up. Older pictures can be moved across on request.

How improvements reach you, and what guards the data

Automatic, and tested before it is released — never after.

3

4

5
CollectedThe server checks every 60 s and restarts itself.
Worth knowing: releases are automatic today

A change saved to the main line of code reaches the live server roughly four to five minutes later, with no human approving the release. That is fast and convenient while we build. Before more people rely on the system daily, we recommend adding a one-tap approval so nothing reaches the live server without you.

3

What protects the data

Layered on purpose: no single measure is the only thing standing in the way.

Getting inEmail and password per person, created individually. No shared account.
On the phoneFace ID unlocks the app; the device passcode always works as a fallback, so nobody can be locked out.
In transitEvery connection encrypted (HTTPS), certificate renewed automatically.
Inside the databaseThe application connects with restricted rights and can only ever see one company's rows.
Administrative accessDirect access to the machine is limited to named addresses; everything else is refused.
If the worst happensEncrypted backup every night at 02:30, plus a monthly automated restore rehearsal.
