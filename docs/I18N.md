# Languages — how the ERP is translated, and how to find what is not

Three languages: Spanish, Catalan, English. Spanish is the hub — every entry is
keyed on its Spanish form, so any pair is one lookup, including English →
Catalan, which has no dictionary of its own.

This document exists because "find the untranslated text" was, for four
sessions, a thing somebody had to notice and report. It is now a thing the
software reports about itself.

---

## For the operator: see the gaps yourself

Add `?i18n=audit` to any workspace URL:

```
https://178-105-10-156.sslip.io/workspace/erp.html?i18n=audit
```

Switch to English or Catalan, then walk the ERP normally. Every element holding
text that has no translation is outlined in red, and a panel in the bottom-right
counts them and lists them. **Copiar** puts the whole list on the clipboard —
paste it into a message and it is a complete, exact work order.

The mode stays on until you press **✕** in that panel, so you can walk several
screens in one pass. It shows only what you actually open, which is the point:
a form nobody opened is a form nobody has read in the wrong language.

Two things it will NOT outline, on purpose:

- **Your own records.** A customer's name, a site address, a surveyor's note and
  a budget chapter title are the same in all three languages. Translating them
  would rename your data.
- **Words that are the same in both languages.** "Total", "IBAN", "App" are
  decisions taken, not lines forgotten.

## For the developer: the four layers

```
site/i18n-dict.js       ES ⇄ EN  — `pairs`, plus `rxEs2En` / `rxEn2Es`
site/i18n-dict-ca.js    ES → CA  — `ca`, plus `rxEs2Ca` / `rxEn2Ca`
site/i18n.js            the runtime: DOM walk + MutationObserver + the ledger
tests/i18n/*.mjs        five gates, described below
```

`tr()` resolves a string in five passes, stopping at the first hit:

1. **Exact match** on the trimmed string, then on the whitespace-collapsed one.
2. **The mixed-page fallback** — a Spanish key, for pages that declare
   `lang="en"` and contain Spanish anyway (`journey.html`, `master-data.html`,
   `financial-data.html`). Without this those strings are unreachable by any
   dictionary entry, which is not the same problem as being absent from it.
3. **Regex rules**, for lines with a number or a date in them.
4. **The decoration pass** — punctuation set aside, the word inside looked up,
   punctuation put back. `"Teléfono: "` is not `"Teléfono"`.
5. **The labelled-segment pass** — for rows where a label and a data value share
   one text node: `"Teléfono: 934771208 · Móvil: 600111222"`.

If all five miss, the string is **recorded in the ledger** and left alone.

## The five gates, and what each one can and cannot see

| Gate                  | Asks                                              | Blind to                     |
| --------------------- | ------------------------------------------------- | ---------------------------- |
| `coverage.mjs`        | does every entry have all three languages?        | strings that are in no entry |
| `audit.mjs`           | do ten static pages differ between languages?     | anything built after boot    |
| `workspace-audit.mjs` | do twelve booted routes differ?                   | anything behind a click      |
| `source-audit.mjs`    | is every literal in the source in the dictionary? | strings built at runtime     |
| **`miss-crawl.mjs`**  | **what did the translator fail on?**              | a screen it never opened     |

The first four all answer the question by enumerating PLACES a string might
live — an entry, a page, a route, a quoted literal. Each of them has reported
clean while an operator was looking at Spanish, because a screen reached by
pressing a button inside a panel is in none of those lists.

`miss-crawl.mjs` does not look for strings. It drives the application — every
route, then every control on each route — and reads off the verdicts `tr()`
already reached. Run it:

```
node tests/i18n/miss-crawl.mjs --lang en --json missing.json
node tests/i18n/miss-crawl.mjs --lang ca --show-excused
```

`--show-excused` prints what the data rules swallowed. Read it occasionally:
every exclusion is a place the audit stops looking, and one of them has already
had to be reverted for hiding twenty-five real alert-rule labels.

All five keep their ceilings in `.github/workflows/ci.yml`. **A ceiling may only
go down.** Under it, the run prints the new number and asks you to lower it.

## Adding a string

Add it in Spanish, then add both translations in the same commit. `coverage.mjs`
fails the build otherwise, and a silent fallback to Spanish is invisible to the
person who introduced it — their own interface is the one language that works.

- one word or phrase → `pairs` in `i18n-dict.js` **and** `ca` in `i18n-dict-ca.js`
- a line with a number or a date in it → a regex rule, not an entry
- a string on an English-authored page → still key it on Spanish; the mixed-page
  fallback will find it
- **never** an entry for a customer name, an address or anything the company typed

## What is deliberately NOT translated

- Money, dates and numbers keep the Spanish format in all three languages. The
  company's books do not change language.
- Anything inside `translate="no"`. A quote is written in the CUSTOMER's
  language, which is a field on the record; the toggle is the OPERATOR's
  language, which is a preference of whoever is at the screen.
- Message-template placeholders (`{{cliente}}`, `{{number}}`). Translating one
  breaks the substitution and posts a literal `{{customer}}` to a customer.
