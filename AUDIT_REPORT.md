## 2. Executive Summary

1. **Verification discipline is real and unusually strong**: 149 browser E2E checks, 5 deterministic simulations, RLS contract tests against live Postgres, a committed-bundle drift check, and a boundary linter with proven violation fixtures — all green at HEAD, all re-verified fresh for this audit.
2. **The shipped product has no authentication, no server, and no durable storage**: the entire business dataset lives in one browser's evictable IndexedDB, saves fail silently, and the only backup is a manual JSON download (F-001, F-002). This is the dominant production risk; everything else is smaller.
3. **The factory API trusts the URL**: any caller can read any tenant's invoices and even trigger an invoice-creating server action by naming the tenant id — RLS keys off a value the request itself supplies (F-001, F-003). Not deployed today, which is the only mitigation.
4. **The release channel is a development branch**: GitHub Pages `/preview` — what the iOS and Android betas load — tracks the active working branch by hardcoded name; it silently served 9-session-old code once already (F-005).
5. **19 high-severity dependency advisories** are open, including a patched-upstream Next.js (16.2.0 < 16.2.5) (F-004).
6. **Two features a construction CRM needs are missing or half-wired**: suppliers/industriales lost their registry screen when Clientes became customer-only (create/edit paths survive only via hidden routes, F-006), and OCR document capture — the one `unbuilt` area in the ownership map — was never started (F-007).
7. **The architecture story and the shipped code point in opposite directions**: the enforced kernel/capability/pack layering governs `packages/`, but the live product is a 5,973-line engine plus a 3,912-line shell in the host layer, with 19 of 27 areas still engine-owned (F-011). The strangler-fig migration exists and works (7 areas factory-owned) but the ratio is the debt figure.
8. **Data-integrity engineering inside the engine is genuinely good**: guarded deletes that name blocking documents, immutable invoices with no delete path, an append-only audit log with user attribution, additive-only migrations with pre-migration backups and a tested intentional-removals ledger.
9. **Legal posture is honest but open**: IRPF retention profiles, invoice-content rules and all AEAT filings are explicitly `legally_verified: false` gates (F-017) — correctly blocked from production use, correctly labelled in the UI.
10. **Accessibility and dependency hygiene are the quality gaps**: pinch-zoom is disabled, drawers don't manage focus, 14 `aria-*` attributes across 24 screens (F-015); prettier drift and an unused workspace dependency round out the polish list (F-019, F-022).
